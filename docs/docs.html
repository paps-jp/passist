1. 概要

PAssist は Windows 向けのリモート操作ツールです。共有するのは選んだ 1 つのウィンドウだけ。 操作する相手はブラウザを開くだけ（インストール・アカウント不要）。映像と操作は WebRTC で暗号化されて流れます。

ねらい：① 開いている任意のウィンドウを1つ選ぶ ② URLを発行 ③ 離れた第三者がブラウザだけで一時操作 ④ デスクトップ全体は絶対に見せない ⑤ アカウント作成なしで入れる。

2. できること（要件と実装）

要件実装
任意のウィンドウを1つだけ選ぶ起動→開いているウィンドウ一覧から選択。キャプチャ元は window のみ列挙し screen は一切扱わない。
URLを発行選択すると共有URL（…/s/<token>）を自動発行・コピー。
ブラウザだけで一時操作WebRTC で映像、DataChannel でマウス/キー操作。相手はブラウザのみ。
デスクトップ全体は出さない選んだ1ウィンドウの映像のみ。構造的に画面全体を渡せない設計。
アカウント不要URLのトークンだけで接続。ログインなし。

3. アーキテクチャ

  ┌──────────────────────── ホストPC (PAssist) ────────────────────────┐
  │  Electron アプリ（タスクトレイ常駐）                                 │
  │   ├─ ウィンドウ選択 / 管理UI（renderer）                            │
  │   ├─ シグナリング/配信サーバ（Node: express + ws）※内部起動         │
  │   └─ 入力注入（nut.js：座標クランプ＋危険キー遮断）                  │
  └───────────┬───────────────────────────────────────┬───────────────┘
              │ WebRTC 映像(DTLS-SRTP)                  │ シグナリング(WSS)
              │ ＋ DataChannel 操作                      │ ＋ ページ配信
              ▼                                         ▼
        ┌──────────────┐                         （UPnP / Cloudflare トンネル）
        │  操作する人    │  ブラウザでURLを開くだけ
        │ ブラウザのみ   │  iframe 埋め込みも可
        └──────────────┘
  • ホスト：Electron 製。ウィンドウのキャプチャ（getDisplayMedia＋setDisplayMediaRequestHandler）、WebRTC の offer、入力注入を担当。
  • サーバ：Node（express + ws）。セッション/トークン管理、SDP/ICE 中継、ビューア配信。ホストが内部で起動。
  • ビューア：ブラウザの素のページ（WebRTC の answer 側）。映像表示と入力送信。
  • 暗号化：映像・操作は WebRTC（DTLS-SRTP）で常に暗号化。シグナリングは https/wss 化可能。

4. 使い方

ホスト（共有する人）

  1. dist\PAssist.exe をダブルクリック（または開発時は npm start）
  2. 共有したいウィンドウをクリックして選択
  3. 表示された共有URLをコピーして相手に送る
  4. 接続リクエストが来たら「許可」（または「この端末を信頼」で次回から自動）

ゲスト（操作する人）

  1. 送られたURLをブラウザで開く
  2. 「クリックして操作を開始」→ マウス/キーボードで対象ウィンドウを操作

タスクトレイ常駐

  • ウィンドウの「×」は終了せずトレイに格納。トレイアイコンのクリックで再表示。
  • トレイ右クリック →「管理画面を開く」「ログイン時に自動起動」「終了」。
未署名のため、初回は SmartScreen 警告が出ることがあります（「詳細情報 → 実行」）。常用ならコード署名を推奨。

5. インターネット公開

方法A：UPnP 自動公開（公開IP＋UPnP有効が前提）

起動時にアプリが UPnP で Web ポート(TCP 8443)を自動開放し、共有URLを http://<公開IP>:8443/s/… に自動設定します。

npm start
# ログに「[host] インターネット公開: http://<公開IP>:8443 …」が出れば成功
# 同一LAN内のみにしたい場合: $env:PASSIST_PUBLIC="0"; npm start

方法B：Cloudflare トンネル（https・ポート開け不要・推奨）

独自ドメイン（例 passist.paps.jp）で正規の https URL になります。Cloudflare 側の公開ホスト名設定は タイプ=HTTP / URL=localhost:8443 / パス=空。

$env:PASSIST_PUBLIC="0"; $env:PUBLIC_BASE_URL="https://passist.paps.jp"; npm start
# 共有URL = https://passist.paps.jp/s/…（ブラウザで開くだけ）
映像/操作は WebRTC の P2P（STUN）で流れ、トンネルは通りません。厳しい NAT の相手とは TURN サーバが必要になることがあります（多人数運用なら中継集約型を推奨）。

6. セキュリティ

観点対策
1ウィンドウ限定キャプチャ元に screen を列挙せず、選択IDに固定。デスクトップ・他ウィンドウは映らない。
一時利用セッションに有効期限（既定30分）。期限切れで自動失効。
勝手に繋がせない既定でホスト承認制。許可するまで映像は流れない。PIN併用モードも有り。
事前承認（信頼端末）承認時に「信頼」した端末は次回から自動接続（端末ごとのクレデンシャル、ハッシュ保存）。
操作範囲の限定入力座標を対象ウィンドウの矩形にクランプ。窓外には出さない。
デスクトップへの脱出防止Win / Alt+Tab / Alt+F4 / Ctrl+Esc / タスクマネージャ 等のキーをブロック。
暗号化映像・操作は常に DTLS-SRTP。シグナリング/ページは https/wss 化可能。

アクセス制御モード（ACCESS_MODE）

approve（既定・ホスト承認）／ pin（6桁ワンタイムPIN併用）／ token（URLのみで即接続）。

7. 信頼性・配信向け堅牢化

長時間稼働でフリーズ／メモリリーク／クラッシュしないための対策を実装済み。

リスク対策
常時ポーリングの負荷対象ウィンドウ矩形の取得を操作中のみの遅延更新に（旧：700msごとに全ウィンドウ列挙 → 廃止）。アイドル時ゼロ負荷。
再接続でのPeerリーク新規接続前に旧 RTCPeerConnection を確実に close＋ハンドラ解除。失敗/切断時も自動解放。
DataChannelのバッファ肥大マウス移動を約60Hzに間引き＋bufferedAmount 上限(256KB)で破棄（バックプレッシャ対策）。
クラッシュレンダラがクラッシュしても自動リロードで復帰（ループ防止付き）。未処理例外/Promise を %TEMP%\passist-crash.log に記録。

8. 設定（環境変数）

変数既定説明
PORT8443サーバの待受ポート
ACCESS_MODEapproveapprove / pin / token
SESSION_TTL_MS1800000セッション有効期限(ms)
PASSIST_PUBLIC有効0で UPnP 公開を無効（同一LAN内のみ）
PUBLIC_BASE_URL—共有URLのベース（トンネル使用時に指定）
TLS_CERT / TLS_KEY—指定すると https/wss で待受
REMOTE_SERVER_URL—外部サーバ利用時のシグナリング先（内部起動を無効化）

9. ビルドと配布

npm install                 # host/server の依存を一括導入
npm start                   # 開発起動（Electron）
npm test                    # 信頼ロジックの単体テスト
npm --prefix host run dist  # 配布用 dist\PAssist.exe（portable）を生成
  • 成果物：dist\PAssist.exe（単一実行ファイル・portable）。サーバ一式は resources\server に同梱、ネイティブ(nut.js)は asar から展開。
  • 入力注入が「閲覧のみ」になる場合は npm run rebuild（nut.js を Electron 用に再ビルド）。

10. iframe 埋め込み

ビューアは普通の Web ページなので iframe に埋め込めます。

<iframe
  src="https://passist.paps.jp/s/<token>"
  allow="fullscreen; autoplay"
  style="width:100%;height:600px;border:0"
  title="PAssist"></iframe>
  • 親ページは https 推奨。allow="fullscreen" は全画面ボタン用。
  • 埋め込み元を限定するなら CSP frame-ancestors を返す（実装可）。
  • sandbox を付けるなら allow-scripts allow-same-origin allow-fullscreen が必要。

11. 制限と今後

現在の制限

  • ホストは Windows のみ（nut.js / WGC）。
  • 厳しい NAT の相手は TURN が必要な場合あり。
  • exe は未署名（SmartScreen 警告）。
  • 操作は OS レベルの実入力（ホストの実カーソルが動く）。

今後の候補

  • TURN（coturn / マネージド）でNAT耐性とコスト管理。
  • コード署名（Azure Trusted Signing 等）。
  • サービス化：中央シグナリング（Workers + Durable Objects）＋ TURN 集約。
  • 送信ビットレート上限・自動更新・アイコン。
